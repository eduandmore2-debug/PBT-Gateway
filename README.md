# PBT-Gateway

Reference implementation and experiment scripts for the paper:

**Purpose-Bound Tokenization: A Lightweight Gateway for Protecting Personal and Banking Data from Hijacked LLM Agents**
Amani Alqarni — Department of Computer Science, College of Engineering and Computer Science, Jazan University, Jazan, Saudi Arabia (ORCID: 0000-0003-3143-3215)

PBT places a gateway between an LLM agent and its tools. The agent receives opaque, session-bound tokens and minimized views instead of real card numbers, IBANs and identity data. The gateway restores a real value only in a typed argument of a trusted tool to which the token is bound (under an amount cap, a use count and a lifetime), or for a single recipient explicitly approved by the user.

## Repository layout

| Path | Content |
|---|---|
| `src/bank.py` | Synthetic banking data generator (300 customers, fixed seed 2026; Luhn-valid test cards, ISO 13616-valid Saudi IBANs, example.com e-mails) |
| `src/gateway.py` | Defenses: B0 no defense, B1 pattern DLP, B1+ normalizing DLP, B2 redaction, B3 naive pseudonymization, and PBT (proposed) |
| `src/experiments.py` | E1 exfiltration (92,400 attempts per defense), E2 utility on ten tasks, E3 attacks against PBT, E4 balance inference through predicates, E5 overhead |
| `src/figures.py` | Figures 1–4 of the paper |
| `results/results.json` | Raw results reported in the paper |
| `figs/` | Generated figures |

## Requirements

Python 3.10+ (results were produced with Python 3.13), `cryptography`, `matplotlib`.

```
pip install -r requirements.txt
```

## Running

```
python src/experiments.py   # -> results/results.json
python src/figures.py       # -> figs/*.png
```

Security and utility results (E1–E4) are deterministic. Timing results (E5) depend on hardware; the reported numbers were measured on a two-core x86-64 virtual machine.

## Data

All data are synthetic and generated by `src/bank.py`. No real personal or financial data are used.
